# 模式与框架库

## 框架一：先问信息从哪来

拿到一个智能任务，别先想"用什么模型"，先问四个问题：

1. 有没有标注好的输入输出对？有 → 监督学习。
2. 有没有一个可以打分的环境？有 → 强化学习。
3. 规则能不能写清楚、是否需要解释？能 → 符号方法或搜索。
4. 有没有另一个会改变策略的参与者？有 → 博弈。

这个顺序的价值在于：它决定了你需要多少数据、能不能解释、上线后怎么维护。

## 框架二：拟合能力与泛化的平衡表

任何模型选择都可以填进这张表：

| 问题 | 加拟合能力的做法 | 加泛化能力的做法 |
|---|---|---|
| 训练误差高 | 加层、加特征、减正则 | — |
| 训练低测试高 | — | 加数据、加正则、剪枝、早停 |
| 两者都高 | 检查标签、检查特征是否有信息 | 换模型族 |

先定位在哪一格，再动手。直接"多训几轮"通常无效。

## 框架三：从"能算"到"算得动"

一个方法在理论上可行，不代表工程上可用。三个常被忽略的成本：

- **时间**：`O(b^d)` 的搜索在 d=20、b=3 时是 35 亿个节点。
- **内存**：核矩阵是 `O(n²)`，n=10 万就是 100 亿个浮点数。
- **标注**：监督学习的效果上限由标签质量决定，不是由模型决定。

评估一个方案时，把这三项写成具体数字，比"效果应该不错"可靠得多。

## 框架四：因果问题的三步检查

看到"X 和 Y 有关系"的结论，按顺序查：

1. 有没有混杂因子同时影响 X 和 Y？
2. 数据是观测来的还是实验/干预来的？
3. 结论说的是"看见"还是"做了会怎样"？

三步都过，才谈得上因果。

## 决策规则

```
if 任务需要逐步推理且要解释 → 符号/搜索优先
elif 有大量标注且模式模糊 → 监督学习
elif 只有评分没有标准答案 → 强化学习
elif 对手会适应你的策略 → 博弈方法
elif 没有标签但想分组 → 聚类
elif 维度太高想压缩 → 降维
```

## 反模式

**反模式一：拿测试集调参。** 调完再报测试成绩，等于自己给自己泄题。必须留一份从头到尾没看过的数据。

**反模式二：用准确率评价不平衡数据。** 99% 的样本是负类时，全判负也有 99% 准确率。要看精确率、召回率、F1 或 AUC。

**反模式三：把"训练 loss 下降"当成"模型变好"。** loss 下降可能只是记住了更多噪声。

**反模式四：先上最复杂的模型。** 先跑一个线性模型或决策树做基线，复杂模型要能明确超过基线才有意义。

**反模式五：忽略数据泄漏。** 特征里包含了标签的信息（比如"是否违约"的后续记录），模型会表现得极好但上线即崩。

**反模式六：把相关性当因果做决策。** 详见第 2 章辛普森悖论；营销、医疗、政策场景里这个错误代价很高。
